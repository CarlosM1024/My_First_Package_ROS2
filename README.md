## Overview

In this guide, adapted from study notes and tutorials on **Robótica con Python (cmorales)** running on **Ubuntu 24.04 LTS**, you will learn how to:

1. Create and structure a ROS 2 workspace using `colcon`.
2. Create a ROS 2 package using `ament_python`.
3. Organize Python nodes (`my_node`, `publisher`, `subscriber`) and expose them via `entry_points` in `setup.py`.
4. Build the workspace/package selectively and source the overlay environment.
5. Run and inspect publisher/subscriber nodes and execute package tests.
6. Version and push the package to GitHub using SSH.

---

## Step 1: Create the ROS 2 Workspace

A **workspace** is a directory that holds your source code (`src`) as well as build, install, and log artifacts generated by `colcon`. By convention, we can name this workspace `ros2_ws` (or `dev_ws`).

```bash
mkdir -p ~/my_ws/src
cd ~/my_ws
colcon build --symlink-install
```

### Key Flags & Directories

- **src/:** Source directory where your ROS 2 packages live.

- **colcon build:** Compiles and installs packages inside the workspace.

- **--symlink-install:** Links non-compiled files (such as Python scripts) directly to `install/` instead of copying them, so edits take effect without re-running `colcon build` every time.

## Step 2: Create a ROS 2 Package

Packages organize nodes, launch files, parameters, and dependencies into reusable units.

Move into the `src` folder of your workspace:

```bash
cd ~/my_ws/src
```

For Python nodes (`publisher`, `subscriber`, etc.), create the package using `ament_python`.

```bash
ros2 pkg create --build-type ament_python my_package
```

### Package Structure (`my_package`)

- `my_package/`: Python module directory containing `__init__.py` and your node scripts (e.g., `my_node.py`, `publisher.py`, `subscriber.py`).

- `resource/`: Package marker file (`my_package`) used by `ament`.

- `test/`: Unit and linter tests (`test_copyright.py`, `test_flake8.py`, `test_pep257.py`).

- `package.xml`: Package metadata and dependencies.

- `setup.cfg` & `setup.py`: Python packaging configuration and `console_scripts` entry points.

---

## Step 3: Nodes & `setup.py` Entry Points

Inside `my_package/my_package/`, this package organizes Python nodes:

- `my_node.py`: Base ROS 2 node script / initial node structure.

- `publisher.py`: Publishes periodic messages to a ROS 2 topic.

- `subscriber.py`: Subscribes to the topic and logs incoming messages.

To expose these scripts as executables via `ros2 run`, register them under `entry_points` in `setup.py` (and verify dependencies in `package.xml` as needed):

```python
entry_points={
    'console_scripts': [
        'my_node = my_package.my_node:main',
        'publisher = my_package.publisher:main',
        'subscriber = my_package.subscriber:main',
    ],
},
```

## Step 4: Build Only This Package & Test Nodes

If your workspace (~/my_ws) contains multiple packages, build only my_package and source the overlay:

```Bash
cd ~/my_ws
colcon build --packages-select my_package --symlink-install
source install/setup.bash
```

### Run Publisher and Subscriber

- **Terminal 1 (Publisher):**

```Bash
source ~/my_ws/install/setup.bash
ros2 run my_package publisher
```

- **Terminal 2 (Subscriber):**

```bash
source ~/my_ws/install/setup.bash
ros2 run my_package subscriber
```

- **Termial 3 (Node & Topic inspection)**

``` bash
source ~/my_ws/install/setup.bash
ros2 node list
ros2 topic list
ros2 topic echo <your_topic_name>
```

## Step 5: Run Package Tests

You can run the package's test suite (`test/`) with colcon:

```bash
cd ~/my_ws
colcon test --packages-select my_package
colcon test-result --verbose
```

## Step 6: Sync with Git and GitHub (SSH)

Keep only the package folder (`~/ros2_ws/src/my_package`) in its own Git repository—avoid committing `build/`, `install/`, or `log/`.

1. Create an empty repository on GitHub (for example, `my_package`).

2. Initialize Git inside `my_package` and push over SSH:

```Bash
cd ~/my_ws/src/my_package
git init
git add .
git commit -m "feat: initial ROS 2 Python package with publisher and subscriber nodes"
git branch -M main
git remote add origin git@github.com:<TU_USUARIO>/my_package.git
git push -u origin main
```

To use the package on another machine or clean workspace later:

```Bash
cd ~/my_ws/src
git clone git@github.com:<TU_USUARIO>/my_package.git
cd ~/my_ws
colcon build --packages-select my_package --symlink-install
```
